# Кулинарная книга со складом

Telegram-бот, который сверяет рецепты с тем, что реально есть в холодильнике.
Карточка 3 лабораторной работы.

## Возможности

- **Виртуальный склад** — учёт остатков продуктов: название, количество, единица измерения (г, кг, шт, мл, л). Добавление, списание, изменение остатка, удаление.
- **База рецептов** — 15 рецептов в комплекте, плюс свои рецепты через бота: время, порции, ингредиенты с граммовками, шаги приготовления.
- **Умный подбор** — `/cook` показывает, что можно приготовить прямо сейчас; `/check рецепт` — чего не хватает и насколько рецепт готов.
- **Список покупок** — собирается автоматически из недостающих продуктов, с отметками «куплено».
- **Хранение** — SQLite, создаётся автоматически при первом запуске.

## Установка

```bash
python -m pip install -r requirements.txt
```

Нужен Python 3.11+.

## Настройка

Скопируйте `.env.example` в `.env` и вставьте токен от [@BotFather](https://t.me/BotFather):

```
BOT_TOKEN=123456789:AAExampleTokenHere
```

Пути можно переопределить, но по умолчанию база и seed-файл лежат в `data/`.

## Запуск

```bash
python -m bot
```

При первом запуске в базу загружаются 15 рецептов из `data/recipes_seed.json`.

## Команды

| Команда | Что делает |
|---|---|
| `/pantry` | Весь склад |
| `/add мука 500 г` | Добавить продукт к существующему остатку |
| `/set мука 200 г` | Задать остаток точно |
| `/rm мука` | Удалить продукт |
| `/consume молоко 200 мл` | Списать со склада, единица необязательна |
| `/recipes` | Список рецептов |
| `/cook` | Что можно приготовить прямо сейчас |
| `/check борщ` | Чего не хватает для рецепта |
| `/build борщ` | Собрать покупки для рецепта |
| `/shop` | Список покупок |
| `/add_recipe` | Добавить свой рецепт |
| `/search сыр` | Поиск по названию |
| `/cancel` | Прервать текущее действие |
| `/help` | Справка |

Всё доступно и кнопками в меню.

### Как добавить продукт

Тремя способами:

```
/add мука 500 г              одна команда
мука 500 г                   прямо в чат, бот разберёт сам
Добавить продукт → по шагам: название → количество
```

По шагам бот спрашивает по очереди и подсказывает формат:

```
Как называется продукт?
Например: Молоко

→ вы отвечаете «Молоко»

Сколько?
Формат: количество и единица, например 750 г.

→ вы отвечаете «750 мл»
```

Единицу можно указывать любую в рамках меры: `5 л` и `5000 мл` — одно и то же,
бот сам переведёт.

### Как добавить рецепт

`Добавить рецепт` → название → время в минутах → порции → ингредиенты →
шаги → `готово`. Ингредиенты и шаги можно присылать в несколько сообщений
подряд, каждый с новой строки:

```
мука 200 г
яйцо 4 шт
сахар 30 г
```

## Форматирование сообщений

Бот отправляет текст в режиме HTML (`parse_mode=HTML`), поэтому в чате видны
жирные заголовки и моноширинные команды, а не сырые теги.

Всё, что приходит от пользователя — названия продуктов, рецептов, поисковые
запросы, тексты шагов — экранируется перед подстановкой в сообщение.
Продукт с именем `<b>жирный</b>` сохранится как есть, но отрисуется обычным
текстом. Telegram отклоняет сообщения с неизвестными тегами, поэтому шаблоны
используют только `b`, `i` и `code`.

## Единицы измерения

Г и кг — одна мера, мл и л — другая. Бот приводит всё к базовым единицам
(г, мл, шт) при записи в базу и показывает удобную: меньше килограмма —
в граммах, килограмм и больше — в килограммах.

```
/add молоко 5 л      → молоко — 5 л
/add молоко 500 мл   → молоко — 5.5 л      (а не 505 мл)
/add мука 2 кг       → мука — 2 кг
/add мука 500 г      → мука — 2.5 кг
```

Поэтому 5 л молока закрывают потребность рецепта в 500 мл, а 1 кг муки
закрывает 1000 г. Сравниваются только однородные величины: 200 г и 200 мл
разными считаться не будут.

Списание работает с любой единицой той же меры:

```
/consume молоко 500 мл
/consume молоко 0.5 л      → одно и то же
/consume мука 200          → единица возьмётся из остатка
```

При попытке записать один и тот же продукт в разных мерах — 200 г и 200 мл —
бот откажется и предложит сначала удалить продукт, иначе сумма была бы
бессмысленной.

База, созданная до появления приведения единиц, конвертируется при первом
запуске: старые остатки в кг и л пересчитываются в граммы и миллилитры.

## Как работает сопоставление

Продукт подходит, если он есть на складе, его мера сопоставима с требуемой
и остатка хватает с учётом перевода единиц.

Названия продуктов сравниваются без учёта регистра и лишних пробелов.

Кнопка «Готово на 100%» не просто информирует: она списывает все ингредиенты
рецепта со склада, а продукты, кончившиеся в ноль, удаляет. Остаток считается
с переводом единиц, поэтому из 5 л молока вычтутся 500 мл и останется 4.5 л.

## Структура проекта

```
bot/
├── __main__.py          запуск бота, DI, роутеры
├── config.py            настройки из .env
├── parsing.py           разбор пользовательского ввода
├── formatting.py        экранирование и сборка HTML-сообщений
├── keyboards.py         клавиатуры
├── states.py            FSM-состояния диалогов
├── domain/              бизнес-логика без знания о Telegram и SQL
│   ├── models.py        dataclass'ы и единицы измерения
│   ├── pantry.py        Модуль 1 — склад
│   ├── recipes.py       Модуль 2 — база рецептов
│   ├── matcher.py       Модуль 3 — подбор рецептов
│   └── shopping.py      Модуль 4 — список покупок
├── storage/             работа с SQLite
│   ├── db.py            схема и подключение
│   └── repository.py    RecipeStorage: CRUD и seed
└── handlers/            хендлеры aiogram по модулям
data/
├── recipes_seed.json    15 стартовых рецептов
└── kitchen.db           создаётся при запуске
tests/                   196 тестов
```

Доменный слой не зависит ни от aiogram, ни от SQLite — вся работа с базой
идёт через `RecipeStorage`, поэтому логику можно тестировать и менять
независимо от интерфейса.
